Getting started

  1. Plug in the nRF52840 USB Dongle. Hit the small white RESET button — its red LED should pulse.
  2. Open the Dongle tab → click Flash sniffer firmware.
  3. Go to Capture → start a session labelled baseline with the target device idle. Stop after ~30s.
  4. Start another session labelled do_X. Perform action X in the vendor app. Stop.
  5. Go to Diff, pick baseline vs do_X — those are the packets that carry the command.
  6. Go to Replay to confirm by sending them yourself, optionally mutated.
  7. Save findings as Protocol Dict entries so future-you (and Claude) can build on them.
Want Claude to drive? Run bt-spy mcp and add it to your Claude config (see docs/user-guide.md).

          No packets in the first 4 seconds. Possible causes:
          
• Active filter dropped everything: if the filter stats above show seen > 0 and dropped = seen,
          your filter doesn't match any captured BD_ADDR. Most common cause: the filter resolved to a
          CoreBluetooth UUID (from a scan) but PL captures real MACs. Run a Probe to bridge UUID→MAC first.
          
• pklg_tail source: PL.app stopped writing, or you pointed at the wrong file
          (click Detect to verify).
          
• nrf_sniffer source: dongle isn't flashed, or no devices advertising in range.
          
• Quick demo: use Probe with Record as to see real bt-spy output without any capture source.

Replay

      
Send a sequence of GATT writes to a real device. Use host BLE — no dongle needed for this part.

      

        
        
        
        
      

      


      
Mutation sweep (automate "try every value of byte N")

      
Send the base payload with one byte (at offset) replaced by every value in [start, end] —
        useful for figuring out "is byte 2 the brightness?" without writing a shell loop.

Long-Term Keys (for encrypted-traffic decryption)

      
If you've paired with a BLE device and extracted its LTK (e.g. from the Mac keychain),
        store it here to attempt AES-CCM decryption of encrypted ACL traffic in future captures.
        Stored LTKs are summarized in the UI but readable only via DB direct access.
